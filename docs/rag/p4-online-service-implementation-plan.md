# P4 在线服务化实施计划（rag/service + rag/dao + rag/controller）

> **目标**：依据 [ragent-porting-gap-analysis.md](../ragent-porting-gap-analysis.md) §9 之 P4 条目，将 ragent-study 的
> 在线服务层（`rag/service` 37 文件、`rag/dao` 22 文件、`rag/controller` 40 文件及其 dto/enums/constant 依赖）
> 完整移植到 mneme-rag，交付**可运行、可测试、可限流治理**的 FastAPI 在线服务。
>
> **口径**：完整重构（非 MVP）——保留 Java 全部行为语义（消息状态机、取消补偿、限流拒绝落库、SSE 事件协议等），
> 框架层（Sa-Token/RocketMQ/MyBatis-Plus）按「能力等价替代」映射到 FastAPI/进程内事件/DatabaseClient。
>
> **本文档只做计划，不含代码改动**。每完成一个步骤，在对应行更新状态并追加「✅ 步骤 N 完成」记录。
>
> **更新记录**：2026-08-19 初版（依据当日代码状态与 Java 基线调研制定）。

### 3.3 技术要点

- **request\_id**：Result 内统一 `uuid4().hex`，exception\_handler 与 Results.success 均填充，对齐 Java convention.Result.requestId；
- **contextvars 与并发**：FastAPI async 端点同事件循环，中间件 set / finally clear 即可覆盖整请求生命周期；`asyncio.create_task` 自动复制当前 context（用户上下文/追踪上下文随之透传，等效 Java TTL）；
- **SSE 队列桥**：event\_handler（回调侧）向 SseQueue push 帧，StreamingResponse 的 async generator 从队列 aiter 消费并 yield 字节；`done` 帧后由发送方 close 队列，生成器自然结束。

### 4.4 技术要点与边界（防重复）

- **与 rag/memory/store.py 的边界**：store.py 服务于**引擎记忆加载路径**（load\_history/append + upsert 会话），已稳定并有并发测试，**一律不动**；`rag/dao/conversation_dao.py` 服务于**会话管理 REST 路径**（分页列表/重命名/删除）。两者写同一张表但职责正交，schema 列名共用 schema.py 单一事实源；
- **与 rag/intent/tree.py、rag/rewrite/query\_rewrite.py 的边界**：只新增管理端**写路径**；写后缓存失效（`IntentTreeCacheManager.clear_cache()` / 术语缓存 clear）由 **service 层**调用，dao 不感知缓存；
- **upsert 语义**：DatabaseClient 无原生 upsert，一律「select → insert/update」两步，dao 内完成；t\_message\_feedback 的 active/cancelled 双路覆盖按 submit\_time 新鲜度判断（对齐 Java 自定义 SQL 语义）；
- **list\_random**：InMemory/SQL 抽象无随机排序原语，dao 内「全量 enabled + random.sample」实现（示例问题为运营配置数据，量级 ≤ 千行）；列表查询统一 `deleted=0` 过滤；
- **activate 事务性**：DatabaseClient 无跨语句事务 API，「清 active + 置 active」两次 update\_rows 之间由 dao 方法内串行完成；InMemory 实现天然原子（RLock），SQL 实现接受短暂中间态（P4 容忍，记录为已知边界）。

**技术要点**：

- **SSE 与引擎的线程模型**：端点内创建 SseQueue → 构造 handler（持有 queue）→ `asyncio.create_task(chat_service.run(...))`（协程内 await engine.execute）→ 端点立即返回 `StreamingResponse(queue.aiter())`。所有回调与生成器在同一事件循环，无跨线程问题；
- **切块语义**：Java 按 codePoint 每次推送 message\_chunk\_size（默认 5）字符；Python 用 `text[i:i+chunk]` 的码点切片（len 按 codePoint 计），思维链与回答分别累积、分别计 type；
- **thinking 计时**：首个 on\_thinking 到最后一个 on\_thinking 的墙钟差，落 `thinking_duration`（毫秒）；
- **取消时序**：stop 端点 → task\_manager.cancel → task.cancel() → 引擎协程在 await 点抛 CancelledError → handler 捕获（chat\_service 协程内 try/except CancelledError）执行取消补偿（落库 INTERRUPTED + cancel/done 帧）→ queue.close。Redis pub/sub 分支：非本节点 taskId 收到通知时查本地注册表（跨节点部署形态，P4 单机也保留监听以对齐语义）；
- **engine 差异**：Java taskManager.bindHandle 绑定 LLM 句柄；Python 引擎 stream\_chat 无句柄（协程级取消），task\_manager 即以协程 Task 为句柄——对外 stop 语义完全一致。
